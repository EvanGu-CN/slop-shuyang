## 六、清单口径与实际数据的不一致

1. **状态码已过时**：清单生成时 ReviewedImagery 仅零星几条，当前渲染集 9,946 栋（解码 9,977、superseded 31）中 ReviewedImagery 已 **2,419 栋**、Overture 6,103 栋、OSM 1,424 栋。清单的 `B`（114 条）/`B2`（33 条）描述的是“只有 Overture 粗块/混合”，现在多数已被影像重建取代——**不能再用状态码判断是否渲染**，本审计全部按当前数据重判。
2. **“空地小区”已不存在**：清单里 `C`（有地块无建筑）共 20 条（批2 15 + 批3 3 + 批5 2），现全部界内有建筑，147 个住宅小区 100% 已渲染。
3. **superseded 会让人误判为缺失**：31 条被替代体块（30 条万顺粗块 + 1 条体育公园用地 `way/1455053507`）仍留在 `buildings-enriched` 里，但 `js/buildings.js` 与 `js/city-map.js` 渲染时排除。本审计已按 `GEO.supersededSourceIndices` 剔除，所以“清单有、渲染没有”不能用 ID 是否存在判断。
4. **公园统计口径**：清单 8 个公园，`park-school-coverage.json` 覆盖 34 个公园（含范围外/无名），不可直接对总数。
5. **清单对“已渲染”的定义偏保守**：无地块的门户设施（车站、场馆、消防站）在清单里多为 `D 仅 POI`，但实际已有 OSM/Overture 建筑或专属模型；反之地块类（公园）有面但无内容，清单 `B` 却显得“已渲染”。两个方向的偏差都已在本审计中纠正。

## 七、逐条明细与复现

- 全 271 条：`render-audit.csv`（含判定依据、未渲染类型、数据可得性、缺口原因、后续批次建议）、`render-audit.json`（同内容 + meta）。
- 判定规则：已渲染 = 渲染集中有归属建筑 / 定制街区模型 / 地标模型；部分渲染 = 有地块、公园面、校区或铺装面但缺楼栋或园路；完全未渲染 = 三者皆无。
