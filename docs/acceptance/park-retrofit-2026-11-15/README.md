## 2. 证据等级、来源与误差

- 全部条目均为 **影像 / 公开资料方位推断**，不是测绘中心线。水平误差 **±6 m**。
- 影像：高德 z18 卫星（GCJ-02 锚定项目原点，0.494 m/px），**2026-11-15 获取**；拍摄日期未知。
- 公开资料（逐园检索，2026-11-15）：
  - 虞姬生态园：`shuyang.gov.cn` 标准地名通知（"南北中心轴""南北两门"）。
  - 沭河公园：江苏省体育局「老沭河健身步道」（3 m 彩色跑道）。
  - 沭阳烈士陵园：宿迁市政府「沭阳烈士陵园」（纪念广场在南侧、纪念碑在广场中央、1975 年建）。
  - 建陵 / 台州路森林 / 城北 / 孙巷：宿迁市绿地名录、沭阳住建与开园报道，只到"有什么"，没有坐标。

  测试会强制校验这些字段存在，并校验中点落在对应公园轮廓内（沭河公园允许距轮廓 40 m，因 OSM 多边形只覆盖河岸绿化带）。

## 3. 本轮发现并修掉的三处渲染缺陷

补线落几何时发现公园内部模块整体不出图，排查后是三处叠加问题（都属于既有代码，非本轮新增）：

1. **坐标形态不匹配**：`PARK_RETROFIT_PATHS` 用 `[[x, z], …]`，而渲染侧按扁平数组解析，
   导致 6 条补线的顶点全部变成 `NaN`；`NaN` 又把整批合并几何的包围盒污染，
   连带 `GEO.mapPaths` 的 65 段园路一起被视锥剔除 —— 也就是此前所有公园"只有绿地、家具缺失"的直接原因。
   修法：接入时 `pts.flat()`。
2. **三角形绕序朝下**：`ribbon()` 的索引 `(0,1,2)(2,1,3)` 生成的法线朝下，默认 `FrontSide` 材质下被背面剔除，
   园路带本身不可见。修法：改为 `(0,2,1)(2,3,1)`，法线朝上。
3. **街区台地遮挡**：虞姬生态园与烈士陵园的大部分面积在 0.22 m 街区台地上，0.095 m 的铺装会被台地完全盖住。
   修法：数据里给这两个公园的条目加 `surfaceY: 0.245`，并把该条园路上的长椅/垃圾桶/园灯/灯下光斑一起抬升
   （`liftGeos`），避免家具半埋。

修复后 `[parkInterior]` 统计（浏览器控制台）：

```
{"pavedPaths":65,"benches":121,"bins":48,"lamps":175,"riverRails":682,"retrofitPaths":4,"retrofitPlazas":2,"parks":5}
```

本轮**没有新增任何 draw call 批次**：补线与既有 `GEO.mapPaths` 走同一套 `mergeGeometries` 批次
（paving / plaza / red / rust / rail / wood / iron / bin / pole / globe / pool）。

## 4. 性能

同一页面，6 个采样点各自测量（浏览器窗口 1400 × 1000，WebGPU）：

| 采样点 | draw calls / 帧 | 三角形 / 帧 | fps |
| --- | --- | --- | --- |
| 虞姬生态园中轴 | 22 | 1 775 252 | 56.8 |
| 沭河东岸步道 | 22 | 2 369 426 | 39.5 |
| 烈士陵园中轴 | 22 | 1 438 260 | 51.8 |
| 城北公园南门（未改动，对照） | 22 | 1 128 579 | 60.0 |
| 万顺帝景天成（基线） | 22 | 2 808 786 | 45.9 |
| 城市中心（基线） | 22 | 1 652 267 | 53.8 |

- **draw call：22 / 帧，与补线前完全一致**，无退化。
- 三角形数差异来自视锥内建筑数量不同（1.13 M–2.81 M），与本次补线的 1 472 m 铺装带（约 2 千三角形）无关。
- fps 39.5–60 的波动与采样顺序、后台编译、机器负载相关；基线点本次也只有 45.9 / 53.8 fps，
  与上一轮 43.5 / 51.5 fps 同量级，**判为环境噪声，不是本轮引入的退化**。
