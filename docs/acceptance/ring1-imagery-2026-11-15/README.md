### 判据修正（影响环 0 与环 1 的 coarse 计数）

环 0 文档里的 coarse 判据是"格内所有足迹 > 900 m²"，会把 80×15 m 的正常 6 层板楼
（约 1,200 m²）误判为合并粗块——凤凰国际城的 Overture 轮廓与影像楼排逐排吻合，
却整片被标 coarse。现改为：**所有足迹 > 2,500 m² 且类别全为 `residential/house/unknown`**。
用新判据重算，环 0 与环 1 的 coarse 均为 0，即两环不存在"建筑与影像明显不符"的合并体块。

## 3. 行排参数怎么来的

沿用环 0 的推导方式，不做手填猜测：

- 行中心 Z 取该地块内**已有足迹的行中心聚类**（10 m 容差）；倾角取已有足迹最小外接矩形
  中位角，并锚定小区质心旋转；进深、单元宽、间距由聚类到的足迹外接框统计得出。
- 没有既有足迹的地块（花都金城、四个只补通道的小区）不推导行排，只补通道/绿地。
- 参数全部写进 `tools/data/shuyang/imagery-districts-traces.json`（`method` 保持 dict，
  新增 `ring1` / `ring1Lanes` 两个键说明推导方式与例外）。

## 4. 实测与推断的区分

- **实测/既有来源**：地块边界、外围道路、地块内原有 OSM/Overture 建筑一条未删未改；
  环 1 没有新增 superseded 标记（`supersededSourceIds` 仍是环 0 留下的 31 条 Overture 粗块）。
- **影像推断**：418 栋 `geometrySource=imagery-reconstructed-row-block`、`heightSource=estimate`、
  `imageAcquired=null`、`referenceId=amap-satellite-z18-20261115-rings`，
  `heightNote` 写明"按 N 层行列住宅推断……不是测量高度"，`geometryAccuracyNote` 写明水平误差 ±6 m。
- **类型判断需要说明的一条**：舒城一品地块 OSM 标 `landuse=residential`，但影像里是
  单层大跨彩钢厂房（含堆场），因此按 `industrial` 重建，并在 traces 里写明这一冲突。
- 院心绿地、河岸带、农田作为 `green` 面写入 `reviewed-district-surfaces.json`，
  带 `geometryMethod`、`referenceId`、`retrievedAt`、`imageAcquired: null`。

## 6. 未做与限制

- 行排仍是街区尺度重建：同排同规格，被既有足迹裁剪，未逐栋测量（声明 ±6 m）。
- 层数为类型化推断（5/6 层砖混、3 层坡屋顶、单层厂房），不是登记层数。
- 未采集地面实拍，因此新补建筑没有实景立面依据；立面、屋顶配色仍是通用渲染。
- 皇冠世纪、金地花园沿街商业立面、围墙、门岗、车位、单元入口均未新增。
- 花都金城只补了绿地，未补楼体：该地块在影像中确实以空地/绿化为主。
