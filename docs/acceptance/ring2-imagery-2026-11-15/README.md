## 3. 行排与通道参数怎么来的

沿用环 0/1 的推导，不做手填猜测，本轮补了两条规则：

- **倾角**：先取地块内已有足迹最小外接矩形的**面积加权 5° 主峰角**；若该角度产不出干净
  通道，再在 5° 网格上搜索"落在无屋顶区域面积最大"的角度。欧洲城 13.4°、健康家园 7.4°
  等均已用放大裁片复核斜率。
- **通道中线**：行中心取同向足迹（±20°）质心在行法向上的 10 m 聚类，车道取相邻两行中线，
  宽度 4.5–7 m（按行距 32% 取，限幅）；再在列向最大缺口（≥14 m）补一条脊线。
  通道带先按地块内缩、再 `difference(existing)` 减去全部既有足迹，**不允许压屋顶**。
- **地面补丁**（`groundPatches`）：只铺空地、不删楼，与 `exclusions`（会同时禁止生成楼体）
  分开。这样停车院/料场/菜地可以整格铺，不会因为格内还压着几栋实测楼而报
  "需复核的删除"。
- 参数全部写进 `tools/data/shuyang/imagery-districts-traces.json`，新增
  `method.ring2` / `method.ring2Ground` / `method.ring2Lanes` 三个键。

## 4. 实测与推断的区分

- **实测/既有来源**：地块边界、外围道路、地块内原有 OSM/Overture 建筑一条未删未改；
  本轮**没有新增 `supersededSourceIds`**，仍是环 0 留下的 31 条 Overture 粗块。
- **影像推断**：299 栋 `geometrySource=imagery-reconstructed-row-block`、
  `heightSource=estimate`、`imageAcquired=null`、
  `referenceId=amap-satellite-z18-20261115-rings`；`geometryAccuracyNote` 写明
  "水平误差约 ±6 m，非实测轮廓"，`heightNote` 写明按影像层数推断。
- **影像推断（通道/地面）**：`sourceSiteId=reviewed/imagery/<district>`、
  `geometryMethod=imagery-inferred ...`，中线误差 ±6 m，宽度按行距比例推定，
  **不是测绘道路中心线**，也不代表通行方向或路权。
- 影像来源：高德 z18 卫星瓦片，拼接底图 `ring2km-mosaic.jpg`，0.494 m/px，
  GCJ-02 反算 WGS84；获取时间 2026-11-15，瓦片本身无拍摄日期，按"2026 年现状近似"使用。

单帧三角形（强制渲染一帧，`info.reset()` 后读数）：城市中心 1.59 M、阳光天地 1.69 M、

**关于 draw call 的口径更正**：这个 three.js WebGPU 构建里 `info.render.calls` 是**累计值**，
`info.reset()` 只清三角形和 draw 分类、不清 calls（实测 reset 前后 calls 不变）。环 1 文档里的
"511 / 588 calls"是把这个累计值除以采样帧数得到的，不能当作每帧批次；本轮改用
"连续两次强制渲染的 calls 增量"，各采样点均为 **24 次/帧**，与几何量无关。也就是说，
环 2 新增几何**没有增加批次**，只增加了单帧三角形数量；帧率仍被垂直同步锁在 56.7–56.9 fps，
未观察到退化。环 1 与环 2 的 calls 数字不可互相比较。

## 7. 限制

- 行排是规整矩形拼接，与真实户型/退界有差别；转角楼、异形楼、坡屋顶朝向未逐栋还原。
- 通道中线来自行距推导 + 影像核对，可能偏 1 个行距；宽度按比例推定，非实测路宽。
- 停车院、菜地、料场按整格近似铺设，边界不是测得的院墙或地块红线。
- 环 2 影像为 z18，0.494 m/px；单片 1–2 像素的附属房（门房、车棚）无法稳定判读，未补。
- 高空视角仍能看到环 3 范围（1500–2000 m，如沭城天下）的大片浅色地面，属下一环范围。
